# Claude 消息无回复修复文档

## 目标

当 Claude Code 的上游线路请求失败时，在聊天记录中显示明确、安全的失败原因和重试建议，避免用户只看到已发送消息并误以为消息丢失。

## 已确认原因

- 2026-10-22 16:56:22 的消息已经由 Code Remote 送入 Claude Code CLI，消息没有丢失。
- Claude Code 通过 CC Switch 请求 `aapi.sevencn.com` 时持续收到 HTTP 502，上游最终在约三分半后结束重试。
- Claude Code 的结构化输出包含 `isApiErrorMessage`、`apiErrorStatus`、上游域名与建议等待时间。
- Code Remote 当前忽略这条结构化错误，只在 CLI 结束后显示通用失败提示，因此等待期间和失败原因都不清楚。

## 实施步骤

1. 从 Claude Code 的结构化 assistant 错误记录中识别 API 错误状态。
2. 缓冲并识别流式 `API Error` 前缀，只提取 HTTP 状态、合法上游域名和合理的重试秒数，不把原始响应、用户内容或认证信息显示到远程界面。
3. 针对网关错误、限流和认证错误生成对应提示，其余情况保留通用失败兜底。
4. 对 Claude 本机历史中的 synthetic API 错误使用同一套摘要，避免刷新或重启后重新显示原始错误载荷。
5. 将提取出的提示写入现有失败消息和完成事件，继续复用当前聊天同步流程。
6. 按 PATCH 更新版本与更新描述，执行生产构建、差异检查，并仅提交本次修改到本地仓库。

## 验收标准

- Claude Code 返回结构化 HTTP 502 错误时，聊天记录显示上游线路故障、HTTP 状态和可用的重试建议。
- 错误提示不包含完整原始响应、请求内容、密钥、令牌或本地代理地址。
- 非 API 错误仍使用现有通用提示，正常回复、工具调用和中断流程保持原有行为。
- Web 与 Android 使用现有消息同步即可看到相同失败内容，不需要新增客户端协议。

## 分类

PATCH / 修复：修正已有 Claude 回复失败时原因不可见的问题，用户完成的任务没有变化。目标版本为 `0.66.2-dev.1`。

## 完成记录

- Claude 实时回复会暂存开头的 `API Error` 载荷；确认失败后只发送整理过的状态、上游域名和重试建议。
- Claude 本机历史中的 synthetic API 错误也使用相同摘要，并标记为失败状态。
- 后端启动时会清理旧数据库中已保存的原始 assistant API 错误和对应侧栏预览。
- 旧库清理只匹配 HTTP 状态码和已知 Claude CLI 错误前缀，避免改写普通回答里对错误文本的引用。
- 正常 assistant 消息必须带 Claude 的结构化错误标记才会按 API 错误处理；普通正文引用不会被误判。
- 已完成 Python 语法检查、生产构建和差异检查；本次不生成 APK，Android `versionCode` 保持 `350`。
