# Android 独立浏览器页面

## 需求与分类

浏览器目前以聊天页上方的可缩放浮窗显示，高度还受聊天输入区、尺寸比例及上下拖拽条限制。用户要求改成独立页面，收起后仍回到左下角地球图标，并继续保留网页状态。

参考 Fluxdo 的完整页面和会话保留行为，继续使用 Dev Wisp 原有原生界面与系统 WebView，不复制 Flutter 代码或 UI。完整页面覆盖聊天区，顶部地址栏、底部浏览工具及系统安全区以外均留给网页；输入法出现时适配剩余高度。

分类为 0.x 界面流程调整 / MINOR：独立浏览器页面取代原来的可缩放浮窗，原先拖拽调整浏览区域的使用方式改变。目标 `0.132.0-dev.1`，Android `versionCode 482`。

## 实施步骤

1. 将浏览器承载从 PopupWindow 改为应用内独立整页，按根视图完整宽高布局，去掉与聊天输入框位置、浮窗比例和拖拽手柄的关联。保留现有主题、地址栏就地编辑、星标、下载、工具及多页切换。
2. 对齐状态栏、导航栏、横屏挖孔和输入法安全区；打开页面时隔离下层聊天的触摸、焦点和无障碍遍历，网页横滑不触发聊天抽屉。返回键依次处理地址编辑、网页历史和收起。
3. 收起只卸载整页承载并暂停当前 WebView，不销毁会话；左下角图标恢复同一实例，不重新加载。显式关闭网页或 Activity 销毁才释放实例；清理时恢复下层界面、输入法和可访问性状态，避免重复挂载或残留遮挡。
4. 更新文档与版本历史，执行现有浏览器相关模型测试和 Android 构建；核对包名、版本、签名并独占归档 APK，验证更新源版本和下载校验。记录未完成的手机交互验收，清理本次临时资源，仅本地提交、不推送、不提前安装、不操作真实聊天。

## 验证结果

- `:app:assembleDebug :app:testDebugUnitTest --offline --no-daemon` 构建成功，97 项现有单元测试通过，无失败、错误或跳过；包含 8 项浏览器模型测试，覆盖页面实例保留、多页切换/关闭、地址安全解析和本地收藏。
- 复核浏览器以 `MATCH_PARENT` 独立页面挂载到应用根视图；已移除浮窗尺寸比例、聊天输入框高度计算和三个拖拽区域。顶部地址栏及底部工具之间由 WebView 占据剩余高度。
- Android 11 及以后使用状态栏/挖孔与 `max(导航栏, 输入法)` 的实际安全区，并在输入法动画回调更新；旧 Android 使用系统原有窗口适配，避免重复留白。浏览器高度不再引用聊天输入区或终端锁定的键盘高度。
- 打开时隐藏下层可见视图并隔离其无障碍遍历，禁用聊天抽屉的触摸识别；清理时恢复下层可见性和原无障碍属性。返回键先处理浏览器，再处理下层设置/终端。
