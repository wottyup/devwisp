## 2026-11-18：DeepSeek 选择题提交后缺少用户回答气泡

分类：修复 / PATCH，目标 Web 版本 `0.135.12-dev.1`。DeepSeek 原生提问已有回答能力，但提交仅解除 Harness 等待并移除卡片，没有生成 Codex 快速选择同样的“问题＋答案”用户消息。本次补齐确认反馈和历史记录，沿用已有用户气泡和 DeepSeek 主题，不改变原生答案协议，不额外发送一轮聊天请求。

### 实施步骤

1. 在原生问题取得已校验答案后、返回 Harness 之前，按问题顺序生成 `1. 问题\n答：答案` 文本；支持多问题、多选、自定义回答及计划反馈。取消、无效或过期提交不生成回答气泡。
2. 将回答持久化到原对话/回合，并广播现有 userMessage 事件；使用问题唯一编号防止重复，复用各端的用户消息渲染。保持 Harness 接收原有结构化答案，不通过普通发送接口重启回合。
3. 验证多选/自定义/乱序答案、取消/重复提交、错误对话隔离、事件与历史一致、刷新及服务重新读取；使用本地模拟模型与真实 Harness 检查继续执行及复用会话时的回合归属。
4. 检查浏览器提交后显示用户气泡及历史恢复，执行相关后端回归、前端类型检查和生产构建；更新版本记录、清理一次性验证资源并本地提交，不推送。

### 验证结果

- 真实 Harness 配合本地模拟模型验证两轮提问：继续复用同一运行时，每轮只新增一条回答消息，事件/历史归属各自原回合，没有多发会话请求；原生计划审核与已有连续会话提问回归通过。
- 服务端覆盖多问题、乱序答案、多选与自定义回答、错误对话、无效/重复提交、用户取消及 SDK 取消、持久化失败可重试、已接受答案与取消同时发生、重开数据库读取。答案先写入数据库再确认提交，通过现有 userMessage 事件显示并随后移除问题卡片。
- 浏览器隔离入口使用真实 HarnessQuestionCard、服务端 broker/SQLite、userMessage 解析与现有 MessageBubble：点击发送后显示一个“问题＋答案”用户气泡，保留 DeepSeek 浅蓝色，多选和自定义文本完整；问题卡移除，刷新从历史恢复且不重复；390px 窄屏没有横向溢出。未访问用户真实聊天或付费模型。
- 本次选择的后端回归 11 项通过；前端类型检查、生产构建和 git diff --check 通过，构建只有现有大 chunk 提示。临时入口、脚本、截图、隔离数据库、浏览器和服务进程均已清理。
- Web 补丁版本 `0.135.12-dev.1`。本次修复包含后端逻辑，需要重启后端服务才能生效，单独刷新网页不足；未在当前活动聊天中重启服务。
