# Windows 网页终端 AI 接管

## 问题与范围

Windows 后端明确返回不支持接管；MCP 仅使用 Unix socket，工具读写仅针对 tmux，前端也以持久化能力限制按钮。不是操作系统权限设置问题。

本次补齐 Windows 本机 PowerShell 和已手动登录的 SSH 终端接管，不接管应用之外的终端。保留用户授权、聊天隔离、手动输入保护。授权绑定本机或具体 SSH 进程；SSH 结束、环境切换或终端更换时撤销授权，不让远程命令落到本机。不自动登录 SSH，也不记录手动输入。

## 实施顺序

1. 添加 Windows 回归测试，确认原实现失败。
2. 以现有 pywinpty 会话为读写入口，使用 VT 屏幕解析及进程树识别 SSH；绑定终端实例与 SSH 进程身份。
3. Windows 使用仅监听回环地址的随机端口和随机认证令牌，Linux 保留 Unix socket；各 AI 引擎注入对应 MCP 配置。
4. 前端按独立接管能力启用按钮，不将 Windows 终端伪装成持久化会话。
5. 运行授权、隔离、SSH 退出、手动输入与真实 Windows PTY/子进程 MCP 验证，构建前端。
6. 本地提交，不自动推送或重启用户正在使用的服务。

## 分类

MINOR：Windows 用户此前无法完成终端接管任务，现在可用；版本为 0.137.0-dev.1。

## 验证与使用限制

- 真实 Windows PowerShell + 独立 MCP 子进程执行单行命令并读回屏幕通过，MCP 标准输出强制 UTF-8。
- 覆盖接管授权、撤销、聊天隔离、终端替换、SSH 进程身份变化与退出、发命令前再次检查、手动输入、认证失败和 Ctrl-C。
- 保留 Linux tmux 测试覆盖；真实 POSIX/tmux 启动测试在 Windows 跳过。
- SSH 身份变化由模拟进程树及工具调用测试覆盖；未使用用户真实服务器登录做端到端验证。
- Windows 终端仍非持久化：终端 WebSocket 关闭会结束该终端，并撤销授权。切换本机/SSH 后需要重新点击交给 AI。
- 接管发命令前检查环境，不声称能消除检查与操作之间操作系统级别的所有竞态。
- 不在本任务自动重启正在使用的服务；更新后重启后端并刷新网页才生效。
