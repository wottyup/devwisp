# 协同群聊

## 目标与分类

按用户明确要求，改为“新建群 → 添加成员 → 聊天”的交互。新群没有必选角色、成员数量、任务表单或创建向导。群内“＋”直接添加 Codex / Claude Code / DeepSeek Harness，可同引擎重复加入；普通单聊从左侧右键加入已有群或直接新建群。沿用单聊历史、共享左右侧栏及逐成员图标。

已重新核实 runner：其 Empty mission 支持先空协同再添加成员，固定 coder/reviewer 是示例 crew，不是通用协同结构；共享 feed/inbox 路由与各自原生会话独立。本轮不把示例双角色强制到新群。新群消息按加入顺序让本轮成员各回复一次，后续成员收到共享群记录；不实现 runner 的终端注入或自主 CLI 收件箱协议。

属于 New Features / MINOR（0.x 下同时覆盖默认交互变更），目标 `0.139.0-dev.1`。旧任务及原API继续可读/可控，新建入口统一为群聊。无新增依赖，仅本地提交，不推送。

## 实施步骤

1. 复核 runner 群与消息机制、现有持久化/调度、侧栏菜单和原生会话接管锁。
2. 扩展现有存储支持空群、动态成员与多轮群消息；复用原生引擎及权限/审批机制，支持单成员、同引擎多成员及三引擎混合。每条消息一轮有界回复，不强制实现/审查结论。
3. 增加建群、加人、移出、发送API，确保幂等、忙碌/队列/目录/归属校验及发送竞争保护。暂停/继续和服务重启保留正在进行的成员回合，不重放未确认派发。
4. 将协同中央页替换为空群/普通聊天布局，在标题旁“＋”直接添加引擎，已有聊天从左侧右键选择群。新建按钮直接持久化群，不出现创建表单；群名默认从第一条消息生成。保留旧任务查看与审批入口。
5. 完成服务/API针对性测试、类型检查、生产构建及隔离浏览器验证（直接建空群、右键新建/加入、重复引擎、混合/单成员、发送重试、暂停恢复、手机布局和旧任务）。不调用真实模型、不重启用户服务。
6. 更新版本和简要说明；清理临时脚本及调试进程，仅提交本任务改动到本地。

## 接管与成员约束

- 已有单聊沿用原生编号与上下文；同一会话同时只属于一个群/任务。运行中、等待审批、含待发送/不明派发的会话先处理完成再加入。
- 首个已有成员可在尚未发言/创建原生成员的群中确定项目目录；已有项目记录的群保持目录一致。
- 成员变更在群空闲时进行，避免本轮收件人变化。移出保留会话和群历史，恢复普通单聊入口。
- 创建、加人、发送采用稳定请求编号；新建成员延迟到首次发言时创建原生会话，点击“＋”不会调用模型。

## 实施与验证结果

已按上述步骤实现动态群聊，复用既有 SQLite 存储、原生引擎适配器及接管保护。空群立即持久化；群内直接添加三种引擎，可重复添加同类成员；左侧右键支持将已有单聊加入新群或已有群。成员移出后保留原生历史并恢复普通聊天入口，群内旧消息仍保留发言者名称。成员及消息请求支持幂等重试，回复与轮次进度原子保存；旧双角色任务保留查看和继续入口。

验证完成：

- 协同服务/API 测试 50 项通过，覆盖空群、单成员、同类多成员、三引擎适配器、接管竞争、目录/队列/归属校验、请求幂等、暂停/重启及不明派发保护。
- 发送可靠性测试 11 项、侧栏与移动手势现有测试 15 项通过。
- TypeScript 检查及 Vite 生产构建通过；仅有现存的大包体积提示。
- 隔离浏览器使用模拟 API 验证直接建群、右键新建/邀请、三种及重复引擎、发送/邀请重试、切群草稿、暂停/继续、移出恢复单聊和旧任务访问；320/390/768/1440 宽度及深浅主题验证通过，无页面错误。已查看桌面、手机及浅色主题截图。

本轮没有调用真实模型、重启用户服务或验证实体手机。新群采用有界、依次回复的共享记录机制，与 runner 的自主 CLI/inbox 路由仍有区别。临时浏览器服务已关闭，临时脚本和构建日志在提交前清理。

## 后端版本未加载的修复计划

用户截图的 `Not Found` 来自协同列表接口。现场核实：运行中的后端早于协同实现启动，`/openapi.json` 中不存在任何协同路由，前端已更新。属于 Fix / PATCH，目标 `0.139.1-dev.1`；不改变群聊能力。

1. 仅将协同接口返回的默认路由 404 转换为明确的后台更新提示，保留真正的会话不存在、认证及其他接口错误；统一侧栏重试按钮样式。
2. 用请求回归测试验证缺失路由与真实资源缺失的区别，运行类型检查及生产构建。
3. 核实实际服务 `codex-remote.service` 与 MainPID；使用既有空闲更新脚本在所有模型回合完成后激活后端，避免打断正在运行的任务。更新后核对健康状态与协同路由。若激活尚在等待，明确报告等待状态。
4. 记录验证结果并仅做本地提交。

修复结果：缺失协同路由、真实群不存在、认证失败、其他接口 404 及后台更新后重试共 6 项请求回归测试通过；TypeScript 检查与生产构建通过。侧栏错误支持换行，重试按钮沿用现有主题样式。运行时根因已通过启动时间和实际 OpenAPI 路由列表验证；本地修复提交后安排独立的、仅在所有回合空闲时运行的更新任务，并在更新后检查健康和协同路由。实际激活结果以更新任务日志为准，未激活前不视为线上故障已消除。
