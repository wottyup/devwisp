# 网页对话历史滚动性能修复

## 目标与分类

改善网页上下滑动、特别是长对话历史的响应速度。属于 Fix / PATCH：阅读、复制、展开历史、查看操作和自动跟随的原有能力保持不变。版本 `0.138.1-dev.1`。不新增依赖，不修改 Android 安装包。

## 实施步骤

1. 使用现有 Chromium/Playwright 和隔离的模拟对话接口，记录长对话滚动的帧间隔、主线程布局/绘制耗时及 DOM 规模；检查滚动事件、后台刷新和屏外内容的渲染开销。
2. 依据测量结果修复主要瓶颈，优先减少屏外历史的布局与绘制、滚动中的重复状态更新；保持可访问性、文本复制、历史展开锚点和主动上翻后的阅读位置。
3. 在相同数据、窗口与 CPU 限速下对比修复前后；检查长单条消息、展开更多历史、底部跟随、代码与表格、桌面及窄屏布局。
4. 执行必要的类型检查、网页构建和差异检查，更新 PATCH 版本和简短版本历史。只提交本次修改，不推送，不包含其他任务的改动。
5. 删除一次性脚本和临时服务，保留有用的验证结果记录。

## 验收

- 相同长对话样本下滚动主线程开销或掉帧得到可测改善。
- 上翻不被拉回底部，展开旧历史不丢失阅读位置，底部仍可跟随新回复。
- 消息文本、复制、代码、表格、原文与操作展开可用，主题和窄屏布局正常。

## 已确认瓶颈与实现

- 隔离桌面 Chromium，1440×1000，4 倍 CPU 限速；40 轮含代码和表格的历史全部展开，原实现产生 72,179 个 DOM 元素。
- 性能轨迹中 Layerize/Paint/HitTest 占据主要成本，滚动脚本和布局不是主要瓶颈。
- 相同内容与高度下，仅给聊天滚动视口单独合成层，并对消息使用 layout/style/paint containment，180 帧样本的主线程耗时从 3.73 秒降至 1.66 秒，超过 34ms 的帧从 27 降至 3。未采用会改变历史高度估算的 content-visibility。
- 历史代码在接近视口 600px 内才生成语法高亮 token；屏外保留完整原始文本和复制能力，已激活的高亮不随滚动反复卸载。

## 最终验证结果

- 完整修复后，同一 40 轮/80 条消息样本的初始 DOM 从 72,179 降至 16,019（约减少 78%），消息滚动总高度保持 311,712px。
- 4 倍 CPU 限速下，首次滚过尚未高亮的代码区域，180 帧主线程耗时 3.03s；重复滚动为 1.95s，对比原实现两次基线 3.73s / 4.09s。重复滚动约减少 50% 主线程开销。超过 34ms 的帧从基线 27 / 31 降至 10 / 8。此为隔离 Chromium 样本，非用户电脑实测。
- 浏览器交互通过：展开旧历史前后锚点偏移小于 3px；屏外代码保持原文、进入视口后高亮；高亮前后文本及完整代码复制一致；表格按制表符复制；收到实时回复后上翻阅读位置保持；回到底部恢复最新消息与跟随；1440px 桌面及 390px 窄屏无水平溢出。无页面异常。
- TypeScript 与 Vite 生产构建通过，保留已有大包体积提示。工作区 pnpm build 自动执行的安装检查受另一个项目既有 appium 构建策略阻挡，因此直接使用本项目已安装的 TypeScript/Vite 执行 package.json 同等构建命令，未新增依赖或修改工作区构建策略。
- 本次仅修改前端性能与版本元数据；4173 预览服务读取新的 dist，刷新网页即可加载，无需中断聊天后端。
- 一次性验证脚本已删除，隔离 HTTP 服务与浏览器均已在 finally 中关闭；测量 JSON 与截图保存在被忽略的 artifacts 目录。
