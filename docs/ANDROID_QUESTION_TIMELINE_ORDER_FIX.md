# Android 选择题消息顺序与卡片居中修复

## 需求与分类

选择题用户回答需要位于 AI 提问前的内容与回答后的继续回复之间，不能将整段 AI 内容统一放在回答前或后。选择题卡片整体需水平居中，题目和选项内容保留左对齐。

本次属于 Fix / PATCH：修复既有对话时序和布局，不增加用户任务。Android 目标版本 `0.129.4-dev.1`、`versionCode 474`；保留历史 APK。

## 实施步骤

1. 核对 Harness 输出累积、问题等待边界、用户答案持久化以及 Android 实时、历史和兼容消息合并路径。
2. 服务端在问题边界分段保存并广播 AI 内容，使每次回答明确夹在提问前段与继续回复之间，保持同一模型回合，不额外发送提示。
3. Android 对旧服务端保留提问时的可验证内容边界，按消息身份及文本前缀恢复真实顺序；没有可靠边界时不猜测或重写历史文本。保留去重、失败重试、跨聊天和连接隔离。
4. 将 DeepSeek 及共用选择题卡片在可用聊天宽度内水平居中，内部内容继续左对齐。
5. 增加消息顺序回归，覆盖实时继续回复、重新打开历史、多次提问与不重复文本；运行适用检查并构建、校验和归档新 APK，覆盖安装到已授权手机。
6. 记录验证范围，清理临时调试资源和进程，本地提交，不推送；保留其他会话正在进行的改动。

## 验证结果

- 服务端在原生 `ask_user_question` / `exit_plan_mode` 工具事件处保存 AI 前段，延续内容使用新消息编号；问题携带 `afterItemId` 和 `timelineVersion`。原生回调等待有序事件流处理边界，避免提问先于前段落盘。没有前段文字时使用同回合最近的持久化消息作为锚点。
- Android 先投影实时文字，再合并已确认回答、再合并远端回答覆盖层，最后进行 AI 消息分组。旧服务端使用提交前捕获的消息编号及精确文本前缀拆分显示，并保留可持久恢复的边界；远端覆盖层不作为清理本地回答的历史确认。
- DeepSeek 卡片及共用选择题卡片的布局参数均设置水平居中，共用卡片父列占满可用宽度；题目、说明及选项仍左对齐。分段后的实时尾段使用自己的文字偏移，原消息编号开始继续输出时会重新建立逐字显示视图。
