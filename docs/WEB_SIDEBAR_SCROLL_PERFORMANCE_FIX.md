# 网页左右侧栏滚动性能修复

## 目标与分类

改善电脑浏览器左侧聊天记录列表和右侧文件树的滚动延迟，保留现有主题、回复呼吸效果、选中外观、搜索、文件夹展开和上下文菜单。属于 Fix / PATCH：原有任务能力不变，修复现有交互性能。版本 `0.138.2-dev.1`，不增加依赖。

## 实施步骤

1. 使用隔离 Chromium 桌面样本和模拟接口，对较多聊天条目、回复中状态及展开文件树进行滚动性能测量，比较帧间隔和主线程耗时。
2. 根据测量结果减少两侧滚动区域的图层和绘制开销；注意聊天行选中背景会延伸到行外，不能直接套用聊天消息的绘制裁剪。
3. 对比相同样本修复前后的指标，验证聊天搜索、筛选、选择、右键菜单、文件夹展开/收起、文件选择与右键菜单、两侧折叠和窄屏打开关闭。
4. 更新 PATCH 版本与版本历史，执行 TypeScript/Vite 构建及差异检查，只提交本次修改到本地，不推送。
5. 删除一次性脚本并关闭隔离浏览器与 HTTP 服务；现有预览服务继续读取构建产物，刷新网页生效。

## 原因与实现

- 桌面侧栏原先没有独立滚动合成层；左侧的回复呼吸动画还持续更新屏外条目的继承 CSS 变量，反复计算样式并绘制。左侧动画占用主线程，也拖慢右侧滚动。
- 为聊天列表和文件树两个滚动视口增加独立合成层。不对聊天行添加绘制裁剪，保留跨出行边界的选中背景和圆角装饰。
- 使用一个共享 IntersectionObserver 追踪回复中条目的可见性，屏外暂停动画，重新可见时恢复并重新参与呼吸同步。同步源排除屏外暂停的条目。
- 使用 React 19 ref cleanup 在条目移除或回复结束时取消观察；每次流式文字更新不重建观察器。没有 IntersectionObserver 时保留原行为。

## 验证结果

- 隔离 Chromium，1440×1000、4 倍 CPU 限速，360 条聊天（29 条回复中）和 601 条文件/目录，分别滚动 150 帧；数据及滚动总高度保持一致。
- 左侧主线程耗时从 16.91s 降至 2.48s；帧间隔中位数从 106.7ms 降至 16.5ms。右侧从 19.20s 降至 3.23s，中位数从 121.9ms 降至 18.5ms。压力样本中两侧主线程开销约减少 84%，非用户电脑实测。
- 样式计算从约 6s 降至约 0.5s。检查到 29 个回复条目中 28 个屏外动画已暂停，1 个可见动画继续；滚入恢复、滚出暂停通过。仅增加合成层仍存在大量样式计算，额外给行添加 containment 没有进一步改善，因此未采用行裁剪。
- 浏览器交互通过：聊天搜索/清空、聊天与文件右键菜单、目录展开收起、文件多选、左右侧栏桌面折叠恢复、390px 手机抽屉打开关闭、侧栏关闭后屏外动画暂停。页面无异常。
- TypeScript 检查、Vite 生产构建、Python 版本元数据编译及 git diff --check 通过；构建仅保留已有的大包体积提示。无需重启后端，刷新网页加载新 dist。
- 测量 JSON 与截图保存在忽略的 artifacts 目录，一次性脚本与构建日志在完成后删除；浏览器与隔离 HTTP 服务在 finally 中关闭。
