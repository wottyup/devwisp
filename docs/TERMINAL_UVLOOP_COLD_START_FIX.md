# 本机终端 uvloop 冷启动修复

## 目标与分类

修复网页顶部终端反复显示“无法启动本机终端。”的问题，保留原有聊天终端与重连能力。属于 Fix / PATCH，版本为 `0.137.3-dev.1`，在当前工作区 `0.137.2-dev.1` 基础上递增一个 PATCH；不添加依赖、不修改 Android 版本、不推送。

## 已确认原因

- 运行日志在终端连接后约 5 秒记录空白的 `Could not start local terminal:`；2026-11-18、19 均有多次记录。
- 使用线上相同的 uvloop 和隔离的 TMUX_TMPDIR 冷启动，可以复现完整异常：`process.communicate()` 等待管道 EOF 超时，随后对已退出进程执行 `kill()` 抛出无文字的 `ProcessLookupError`，覆盖真正原因。
- 标准 asyncio 下原来的三项测试通过，未覆盖 Uvicorn 自动选择的 uvloop。uvloop 使用的子进程输出通道与 tmux 守护进程冷启动组合导致 EOF 等待不结束。
- 现场旧 systemd keeper 仍指向 codex-remote socket，而应用已使用 devwisp socket；这使服务重启后更容易冷启动。修复应直接支持冷启动，不依靠现场 keeper 掩盖问题。

## 实施步骤

1. 将短时 tmux 管理命令改为在线程中使用标准库 subprocess.run，使用普通管道、明确超时与子进程回收，不阻塞异步服务。保留命令输出与错误语义。
2. 启动失败日志保留异常类型和堆栈，空文字异常在网页返回类型信息，避免只有通用提示。
3. 在现有真实 tmux 隔离测试上覆盖 uvloop 冷启动、并发启动和保留 shell 状态重连；补充超时及非零退出错误传播验证。
4. 运行终端启动与接管测试、差异检查；记录 PATCH 版本与版本历史。只暂存本次变更，保留工作区其他任务的修改，完成本地提交。
5. 验证完成后，若线上有运行中的回复则不重启打断，说明生效条件；所有隔离 tmux 服务及临时调试进程及时清理。

## 验收

- 标准 asyncio 与 uvloop 下，从不存在的 socket 启动终端均可执行命令。
- 不同聊天同时冷启动成功，同一聊天重连保留 shell 状态。
- 超时与非零退出具有明确错误；不对已退出进程再次发 kill 导致空白错误。
- 不操作其他项目的 tmux 服务、终端或进程。

## 验证结果

- 修复前：使用 uvloop 的独立冷启动探测连续 10 次复现 5 秒超时与空文字 ProcessLookupError；标准 asyncio 原有三项测试全部通过。
- 修复后：终端启动、错误传播与接管共 17 项测试全部通过；真实 tmux 在标准 asyncio 和 uvloop 下均完成冷启动、并发和状态保留重连。
- 所有探测使用隔离 TMUX_TMPDIR，结束后关闭对应 tmux server，临时目录自动删除，没有留下脚本或调试进程。
- 当前后端仍承载聊天任务，未重启打断。源代码修复在后端下次重启后生效。现场旧 keeper 配置未修改。
