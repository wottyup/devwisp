# Android 终端恢复与跨屏复制修复

## 需求与分类

终端加载失败、连接断开或退出后，需要在当前终端中直接重试。终端长按选择应能跨屏滚动并保留已选内容，持续输出不能清除选区。

本次属于 Fix / PATCH：完善已有终端的恢复入口及复制体验，不改变用户可执行的任务。目标 Android `0.129.5-dev.1`、`versionCode 475`，安装包使用新文件名，保留历史版本。

## 实施步骤

1. 对照网页的重连行为，核查 Android 连接状态、旧 WebSocket 回调、原生选择及终端画面缓冲。
2. 顶部新增重启按钮，重新建立当前终端连接，沿用聊天标识和工作目录，以恢复服务端保留的会话。连接中防止重复点击，超时和失败后恢复按钮，关闭时清理回调；旧连接不能覆盖新连接状态。不终止保留会话中的命令。
3. 将原生终端输出改为固定可见区域内滚动，增加有上限的历史缓冲，保留离开屏幕的行；滚动查看时保持位置，在末尾时跟随输出。
4. 选择期间固定显示快照、继续接收后台输出；取消选择后恢复显示。取消焦点抢占，保留屏外选区和原生选择手柄，支持带选区滚动及系统复制。
5. 增加有意义的缓冲和状态回归，验证终端控制序列、历史上限、重新连接及持续输出时的选择稳定性；构建、校验新 APK，按已有授权覆盖安装到手机，仅执行启动及独立验证，不操作用户聊天或发送终端命令。
6. 更新版本摘要及验证结果，清理本次临时文件和进程，本地提交，不推送，不纳入其他会话的工作。

## 验证结果

- 顶部新增“重启”按钮，沿用当前聊天标识和工作目录重新建立 WebSocket，行为与网页重连一致。连接中禁用重复操作，20 秒未就绪会恢复重试入口；错误、退出及关闭均结束等待，保留首个错误原因，旧连接和失败连接的延迟回调不会恢复或覆盖新状态。关闭终端时移除超时回调。
- 原生终端缓冲提取至 `TerminalScreenBuffer.kt`，保留最近 2,000 条历史行，并以 500,000 字符额外约束历史内存；tmux 状态栏不加入正常历史，应用内部局部滚动不污染历史。显式清历史和重置控制序列得到独立处理，缩小窗口时保留离开视口的行。
- `TerminalOutputView.kt` 使用固定可见区域及原生文本滚动，支持屏外选区、正反向选择和系统复制。选区存在时不替换显示文本，后台缓冲继续接收；结束选择后恢复显示。带选区拖动时保留端点，选取时隐藏透明输入层、停止抢占焦点及延迟尺寸修改，避免屏幕底部的输入控件截走复制手势。滚动查看时保留位置，位于末尾时跟随输出。
