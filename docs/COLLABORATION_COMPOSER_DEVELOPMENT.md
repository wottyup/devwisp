# 协同共用输入框与提示折叠

## 用户要求与分类

1. 协同群聊直接使用单聊的 `MessageComposer`，共用草稿、粘贴、附件、翻译、模型/权限、排队与定时、编辑队列和暂停/继续等功能。
2. 成员原生会话里的协同上下文提示默认折叠，手动展开后保留完整内容，历史提示同样处理。
3. 保留群内直接加模型以及从已有单聊加入两条入口，不要求先建单聊。

新增群聊附件与发送管理能力，属于 New Features / MINOR，目标 `0.141.0-dev.1`。折叠属于体验修复，一并发布。无新增依赖，仅本地提交，不推送；不使用真实模型做验证。

## 实施步骤

1. 将现有单聊输入框属性整理为共享配置，协同页面通过渲染接口使用同一个组件；以群编号隔离草稿、附件和发送状态，模型设置只应用到对应引擎，混合群成员保留独立引擎配置。
2. 让现有共享队列识别协同群为独立发送目标，复用持久化、翻译、定时和编辑/移动等机制；群消息按原规则有界顺序回复。单聊继续使用原有适配器及每会话锁，避免重复取锁。群的暂停/继续、即时追加与队列状态同步，不重放未确认发送。
3. 扩展群消息保存和原生适配器转发，支持图片、文本/原始文档与每轮模型/思考/权限。附件标识沿用现有上传存储；仅在实际发送时生成临时文件，失败清理，不在侧栏列表暴露二进制内容。
4. 用严格的协同提示识别规则，将消息正文包在默认关闭的详情节点内。保留原文复制、附件和时间；不折叠普通用户消息。
5. 完成针对性服务/API/输入框测试、类型检查、构建及隔离浏览器验证，重点覆盖单聊隔离、混合引擎、排队及幂等重试、附件、翻译与默认折叠。
6. 更新版本和简要历史，本地提交。先验证后台接口再切换新前端；空闲后更新以避免中断模型任务。清理临时验证脚本、调试进程及构建目录。

## 完成与验证

- 协同页通过适配器渲染原 `MessageComposer`；群编号隔离草稿、图片草稿、设置和队列。文件树加入文档直接使用原组件附件接口。混合引擎设置无需在发送前必选；编辑队列保留其他引擎原快照与附件，编辑期间锁定引擎切换。
- 群队列复用既有持久化、定时、后台翻译和编辑锁；直接调用原生引擎发送，不重新进入 HTTP 发送锁。群完成唤醒队列，暂停/继续同步队列，解散只清理该群队列。附件事件兼容旧数据库迁移。
- 原生成员历史完整提示以默认关闭的 details 呈现，支持 CRLF 历史；展开原文、复制与普通消息保持可用。群内“＋”直接添加引擎、已有单聊右键加入两条入口均保留。
- Python 协同服务/API **75 项通过**，涵盖三引擎附件与模型/权限、幂等重试、忙碌排队及编辑锁、暂停/恢复、追加消息及后续成员上下文、后台翻译、定时/解散隔离、数据库迁移、群运行时普通单聊独立发送。另补测 PDF 原件在三个引擎的转发通过。
- 单聊发送锁与带设置插队的 **3 项专项回归通过**。JS 输入快捷键、草稿、附件、队列恢复与提示识别等 **26 项通过**；英文字典占位符校验 **1 项通过**。
- TypeScript 类型检查、隔离目录生产构建通过。Vite 提示现有大资源块；未增加依赖。pnpm exec 自动触发了上层 workspace 安装检查，因既有 appium 构建策略未完成；后续直接使用 workspace 内现有 TypeScript/Vite 二进制完成验证，无项目依赖修改。
- 隔离 Chromium 使用假 HTTP/WebSocket 数据，无真实模型调用：验证默认折叠/展开、普通消息不折叠、群切换草稿恢复、群与单聊隔离、文档上传、图片粘贴、切换引擎后编辑队列保留其他引擎快照、定时、后台翻译以及 1440px/390px 布局；无页面异常。
- 扩展运行旧 `tests/uiLanguage.test.mjs` 时，3 项动态模块测试因测试加载器未处理既有 `legacyStorageMigration` 相对导入而失败；该测试仍使用迁移前 storage key。本次未修改该旧测试框架；英文字典检查及浏览器实际加载通过。共享队列既有 busy-Claude 断言差异亦不纳入本次通过声明。
