# 右侧文件树滚动延迟修复

## 目标与分类

针对上一轮侧栏优化后，电脑浏览器右侧文件树仍然滚动延迟的问题继续测量与修复。属于 Fix / PATCH：改善既有文件浏览性能，不改变用户任务能力。计划版本 `0.138.4-dev.1`，不增加依赖。

## 实施步骤

1. 在隔离浏览器中构建数百至数千条文件的样本，记录滚动帧间隔、主线程耗时与绘制事件，并验证原生滚轮输入；对比图标和屏外绘制等因素。
2. 根据测量定位的瓶颈减少文件树的渲染或绘制成本，滚动中暂缓鼠标悬停重绘；保留主题行高、展开层级、分页、选择、右键菜单、键盘访问和滚动位置。
3. 使用同一样本比较修复前后数据，验证目录展开/收起、分页、多选、文件预览、菜单以及窄屏交互；执行 TypeScript 与生产构建检查。
4. 记录结果并更新 PATCH 版本、简要版本历史，只提交本次修改到本地，不推送；保留已有未提交的协作页面修改。
5. 删除一次性测试脚本并关闭本次启动的浏览器和隔离 HTTP 服务，保留既有服务。

## 测量与结果

### 定位与实现

- 上轮已暂停屏外聊天呼吸动画，但鼠标位于右侧文件树时，滚动不断切换经过条目的悬停状态。所有已加载条目挂在同一绘制范围内，数百个文件及 SVG 图标产生大量重复绘制。
- 隔离样本原版追踪中，150 帧 Paint 累计约 7.15s，Layout 为 0。隐藏图标只改善一部分；逐行 content-visibility 虽然减少绘制，却增加交叉检测、布局和图层开销，不采用。
- 每个目录的兄弟条目按 16 项分组，用 content-visibility 跳过屏外组。先统一解除跳过、批量读取真实组高度、再批量启用，避免猜测行高导致滚动高度改变。目录展开保留其他目录条目的 DOM 和键盘焦点。
- 数据、主题、视口宽度及字体变化时重新测量；监听器、ResizeObserver、动画帧和滚动计时器在卸载时清理。不支持 content-visibility 的浏览器仍正常渲染完整列表。
- 滚动时仅暂停条目的鼠标悬停样式，停下 150ms 后恢复。保留选中与键盘焦点样式，原生滚轮、点击和右键输入保持可用。

### 验证

- 桌面 Chromium、1440×1000、4 倍 CPU 限速、360 个聊天和 601 个文件/目录、鼠标停在树内、150 帧滚动。在同一构建中关闭分组跳过并恢复原悬停样式作对照：TaskDuration 7.9756s → 3.2121s（降低约 60%），帧间隔中位数 50.1ms → 19.2ms，超过 34ms 的帧 149 → 21。总高度同为 18650px，条目全部保留。这是隔离压力样本，不代表用户电脑实测。
- 展开目录内 3000 个文件、合计 3041 个条目：TaskDuration 13.8824s → 3.9388s（降低约 72%），帧间隔中位数 74.0ms → 19.6ms，超过 34ms 的帧 149 → 21。总高度同为 94290px，完整数据与文件图标保留。
- 7 种桌面主题、6 种手机主题在顶部、中部、底部往返后的高度与关闭跳过渲染时一致；复古桌面样本行高不同，总高度 15033px 仍保持稳定。复古手机版使用既有边缘手势，未纳入工具栏按钮的手机测试。
- 浏览器验证通过：原生滚轮、滚动时暂停及停下恢复悬停高亮、指针输入保持启用、目录展开/收起和分页、多选、右键菜单、文件预览、跨组 Tab 导航、展开目录后兄弟节点与焦点保留，以及手机抽屉关闭/重新打开时保留滚动位置。页面无异常。桌面切换聊天后的滚动位置仍沿用原有行为，本次仅保证绘制跳过不改变高度。
- TypeScript 检查、Vite 生产构建、20 个相关 Node 用例、Python 元数据语法与 git diff --check 通过。构建仅出现既有大包提示；无新增依赖。
- 数据保存在忽略的 artifacts/tree-scroll-final-600.json、tree-scroll-final-nested-3000.json 和 tree-scroll-themes.json；桌面/手机截图同目录。隔离浏览器与 HTTP 服务在 finally 中关闭，一次性脚本和构建日志在完成后删除。既有服务不重启，刷新网页加载新构建。
