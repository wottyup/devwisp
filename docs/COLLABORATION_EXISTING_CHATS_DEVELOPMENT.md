# 已有单聊加入协同开发文档

## 目标与分类

创建协同时，每位实现者/审查者可选择新建会话或已有单聊。已有会话沿用原生会话编号及历史上下文，不复制对话，不重新发送旧消息；加入后由任务统一调度。复用现有左右侧栏及成员标题图标。

这是新增用户能力，分类 New Features / MINOR，目标版本 `0.138.0-dev.1`。不增加依赖，不推送远端。

## 实施步骤

1. 检查原生恢复、发送及队列的互斥机制，确定已有会话接管边界。
2. 后端支持可选成员会话编号：校验存在、引擎、工作目录、成员唯一性及归属；拒绝正在运行、有排队消息或发送状态不明的会话。在发送共用锁内完成校验和持久化归属，避免并发发送与重复接管。
3. 调度直接继续原生会话，保留历史；恢复 Codex 原生会话，维持实现者可写/审查者只读权限。保留创建请求的幂等重试。
4. 新建协同表单提供已有单聊选择与上下文/接管说明；排除另一角色已选会话，协调项目目录。错误时保留草稿。
5. 增加针对性服务/API测试，完成类型检查、生产构建及隔离浏览器检查（新建/复用混合、重复选择防护、错误保留、手机布局）。不调用真实模型或重启用户服务。
6. 更新版本、简要历史与说明，记录验证边界；清理临时脚本及调试进程，仅本地提交本任务改动。

## 验收重点

- 已有单聊的原生历史保留，协同新回合追加到同一会话。
- 两角色不可选同一会话，已属于任务的成员不可再次接管。
- 有运行中回复、队列消息、未确认派发或不同项目目录时拒绝接管，保持原会话不变。
- 创建幂等、发送竞争与服务重启不会形成双重调度或孤立任务。
- 标题图标、共享左右侧栏和原有新建成员流程继续正常。

## 实施与验证结果

- 已完成两角色的新建/已有单聊选择，支持标题、目录和引擎搜索。首个已有成员决定项目目录，另一角色不能重复选择同一会话或选择不同项目；混合新旧成员与两位已有成员均可创建。加入后从任务打开成员记录，原生编号与历史不变。
- 后端在成员接管锁和既有发送锁内检查归属、原生状态、队列及派发屏障，然后原子保存任务和成员归属。拒绝忙碌、待审批、未确认发送、待发送/定时消息、目录不符、引擎不符及终端接管中的会话。拒绝时不修改原对话或队列。
- Codex 在同一原生会话恢复上下文，再按角色施加回合权限和任务目录；Claude Code / DeepSeek Harness 沿用已有原生会话。既有审查者只读/plan策略保持。普通聊天变更在接管锁内重新检查归属；即使原HTTP请求断开后幂等发送回调继续执行，也会在发送锁内阻止接管后的单聊发送。
- 创建失败保留要求和成员选择，同一请求编号支持幂等重试；成功后新任务草稿清空成员引用，避免复用已经归属任务的会话。
- 验证：协同服务/API测试37项、既有发送可靠性测试11项、侧栏/搜索/分组/手机手势测试15项通过；TypeScript与Vite生产构建通过，保留既有大包体积提示。
- 隔离HTTP/WebSocket浏览器检查通过：搜索、目录锁定、重复及跨项目选择防护、409后草稿保留、同请求编号重试及响应丢失后归属列表已刷新时恢复原任务、双已有成员及新旧混合请求、已归属成员过滤、逐成员图标与320/390/768/1440px布局。截图位于忽略的 `artifacts/existing-chats-*.png`；没有浏览器运行异常。
- 未调用真实模型、未验证实体设备、未重启当前用户服务或部署。无新增依赖。一次性浏览器脚本和构建日志清理后，仅本地提交本任务代码、说明及版本记录，不推送；保留其他并行任务的改动。
