# 群聊并行讨论与分工开发

## 需求与分类

同一个群内直接发送需求，不增加开关、页面或必填设置。先让被点名的成员（未点名时为全员）并行只读讨论；需要实施时，收齐讨论结果，再生成明确的负责人、文件范围与依赖，按分工开发，最后汇总。开发使用独立工作目录，防止同时修改共享源目录。

分类 New Features / MINOR，目标版本 0.143.0-dev.1：新增并行讨论、自动分工与隔离开发能力。仅本地提交，不推送、不部署，不调用真实模型做验证。

## 实施步骤

1. 将新群聊轮次改为持久化的并行只读讨论，所有成员使用相同的轮初记录；保留老轮次恢复路径。保存多个活动回合，暂停、恢复、重启和解散均不能重复派发或遗漏成员。新消息在当前完整轮次结束后再处理。
2. 从成员的内部实施请求进入只读方案汇总；只有规划器确认当前用户要求开发、任务负责人/文件范围/依赖合法时才执行。协议内容不展示为普通群消息。纯讨论到本轮结束即停止，不无限自循环。
3. 为开发任务建立当前源码的独立快照/工作目录。互不依赖且成员、文件范围不冲突的任务并行；重叠文件和前置任务按顺序执行。后台校验实际变更范围、源文件是否被外部修改；冲突或越界时保留工作成果并暂停，不覆盖源码。原有未提交修改必须包含在快照且得到保留。
4. 所有开发结束后进行只读汇总，结果回到群记录；界面只显示当前阶段、活动成员与可打开的原生会话，沿用已有输入框和控制。
5. 补充并行屏障、只读权限、计划验证、文件隔离/合并冲突、依赖执行、暂停恢复及普通单聊回归测试。完成类型检查、生产构建和浏览器验证，更新版本与简要历史，本地提交，清理临时验证脚本与进程。

## 实施边界

- 内部规划与汇总均为有界调用；无法形成可靠分工时留在讨论，不自行猜测写入范围。
- 独立工作区避免共享目录的正常写入竞争；执行阶段仍强制各引擎现有的工作区权限，后台只将指定文件的合法差异合入源目录。
- 失败或冲突的开发目录保留用于恢复/核实；成功合入后的临时目录清理。运行服务不在本轮重启。
- Git 工程使用 detached worktree 并叠加当前已修改/未跟踪的源码；普通目录和未提交过的 Git 工程使用过滤后的独立副本。复用现有 Node/Python 依赖，Node 构建缓存保留在各自目录，不自动安装或修改共享依赖。
- 超长上下文按成员均衡节选，确保上一轮每位成员都有记录进入下一轮；完整消息仍保留在群记录。符号链接源码不自动合入。

## 完成与验证

- 实现四个阶段及多个活动回合的持久化。仅当前轮次所选成员参与讨论和分工；本轮第一位成员负责只读整理方案与最后汇总。没有实施请求时只进行一轮讨论；规划无效或仍需讨论时不进入开发。
- 强制 Codex readOnly/workspaceWrite、Claude plan/default、DeepSeek read-only/workspace-write 的阶段权限；模型与推理等级快照保留。内部规划协议不显示在群记录。任务未确认完成和验证通过时不合入，也不释放前置依赖。
- 独立目录检查实际修改范围和源文件指纹；支持新增、删除、二进制与权限变更及合入后重启的重复核对。冲突保留成果，不覆盖外部改动。已经合入的任务不会重复执行；旧顺序轮次仍按旧路径恢复。
- 浏览器验证覆盖中文桌面、390 px 手机触控和英文桌面：各阶段与多人状态、无新增开关、@ 点名、普通发送和 Ctrl+Enter 保留排队、开发会话打开与输入限制、审批提示及汇总完成后的状态恢复。修复新执行会话首次打开时共享成员列表尚未刷新的时序问题。
- TypeScript 类型检查和生产构建通过；另外在真实项目创建的独立工作目录中实际运行类型检查与生产构建，确认原项目源码和构建缓存均未改变。Vite 仍有既有的大产物体积提示。
- 协同后台定向测试 104 项通过；单聊队列防重复加锁及显式插队回归 3 项通过；前端点名、折叠、输入法和快捷键测试 10 项通过；英文占位符检查 1 项通过。
- 所有模型接口均使用模拟实现，未向真实模型发送测试请求；未运行整仓全量测试。仅本地提交，未推送或部署，运行中的服务尚未加载本次更改。
