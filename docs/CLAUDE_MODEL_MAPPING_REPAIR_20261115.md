# 本机 Claude 模型映射修正

## 目标与范围

统一本机 Claude CLI 的实际请求模型与 CC Switch 当前供应商已配置的 mercury-3，避免角色名解析为残留的 claude-opus-5、claude-sonnet-5 等名称。不更改 API 地址、认证、权限、历史记录或上游内容过滤规则，不重启网页服务。

## 已核实证据

- Claude 全局 settings.json 的四个角色实际模型仍为 claude-*-5 系列，显示名称均为 mercury-3。
- CC Switch 的当前 newapi 和 Mercury 供应商保存的实际模型映射均为 mercury-3，无需修改其数据库。
- 最近网页聊天保存的选择是 default，而非显式指定 claude-opus-5。
- 2026-11-15 15:00:57、15:01:54 的 HTTP 400 错误载荷为 content_filter_error。失败日志保留请求模型名称，不能据此断定真实上游切换到了同名模型，也不能把该 400 归因于模型不存在。

## 实施步骤

1. 检查配置一致性，确认现有四个实际模型映射不符合预期。
2. 在本机原目录备份配置，不把配置或认证内容纳入仓库。
3. 仅将四个角色的实际模型和默认请求模型统一为 mercury-3，保留所有其他设置。
4. 校验 JSON、模型映射、其他字段未改变，以及 CC Switch 供应商映射一致性。
5. 不终止现有进程；后续新启动的 Claude 对话进程读取新配置，已有进程可能保留旧值。

## 验收边界

配置校验可证明新进程的默认模型映射已修正，但不能证明上游不会内容过滤、不会提前结束回答。没有发送真实会话探测请求，也不绕过安全过滤。
